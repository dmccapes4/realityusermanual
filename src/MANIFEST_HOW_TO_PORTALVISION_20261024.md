## The Roll Scheme

**Why random order:** A manifest declares what is present. It does not rank. Alphabetical order privileges the letter A. Chronological order privileges early work. Thematic clustering would impose a reading order the documents did not ask for. A dice roll imposes no judgment on the content; it only determines sequence. The sequence is then fixed and documented, so the reader knows it is arbitrary and can navigate accordingly.

**The scheme:** Each of the 22 documents was assigned an alphabetical index n (1–22). The roll was computed as:

```
roll(n) = ((n × 7) + 13) mod 20 + 1
```

This is a linear congruential generator with multiplier 7, increment 13, modulus 20, offset 1. It produces values in [1, 20]. The parameters (7, 13) were chosen because 7 and 20 are coprime (ensuring full-period traversal) and 13 is a prime increment that avoids the early-period clustering of small increments.

**Ties:** Two pairs of documents produced the same roll value. Tiebreak rule: longer document name wins (name length as proxy for title complexity). Ties still tied after name-length were resolved by name-length of the full path (more deeply nested = higher tiebreak roll).

**Ordering:** Highest roll appears first (position 1). Lowest roll appears last (position 22).
