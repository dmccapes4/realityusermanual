## The manual that the title promises

REALITY_USER_MANUAL is named correctly. It is not a book about reality. It is the manual
for operating within it. The title is a contract with the participant: here is what you
need to know to use this system. The system is reality. The participant is the operator.

`run_full_verification.sh` is that manual. It is 1705 lines. It is not a CI script. It
is the gate. The participant runs it and receives the complete specification of what they
are entering: the epistemic framework, the primitives, the invariants, the operator
contract, the one promise. Then the quiz. Then, if they pass, the system proceeds.

Phase 1 ends. The script closes Phase 1. Phase 2 begins.

An agent reduced this to a shell script that checked whether eight files existed and
called it verification. The agent read "verify" and filed a checksum. The checksum is
not what was being verified. What was being verified was the participant's understanding
of how to operate in a system that treats the accrual of knowledge as a responsibility.

## `set -e`

The manual opens: `set -e`. Before light or language there is agency.

`set -e` is not a bash option. In this context it is the declaration that this system
exits on error. An error is not something to continue from. An error is the condition
that ends the current process and returns control to the operator. The system does not
swallow errors. The system does not proceed past them. The operator sees the error and
decides.

This is epistemic humility at the interpreter level. It predates every line of the
manual that follows it. It is the baseline invariant from which everything else is
derived: errors surface; nothing proceeds without acknowledgment.

The participant who reads the manual and reaches the quiz and fails the quiz three times
encounters `exit 1`. The system exits with error. State is preserved. The invitation is
to return. The exit is not punishment. It is boundary enforcement. It is `set -e`
manifested at the epistemic gate.
